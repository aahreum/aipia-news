현재 브랜치에서 main 브랜치 대비 커밋된 내용을 분석해서 PR 초안 마크다운 파일을 생성해줘.

## 진행 순서

1. 아래 명령어를 실행해서 브랜치 정보와 변경 내용을 파악해.
   - `git branch --show-current` — 현재 브랜치명 확인
   - `git log main..HEAD --oneline` — 커밋 목록 확인
   - `git diff main...HEAD --name-only` — 변경된 파일 목록 확인
   - 변경된 파일 중 핵심 파일들을 Read로 열어서 실제 구현 내용 파악

2. 분석한 내용을 바탕으로 `docs/pr-{브랜치명}.md` 파일을 생성해.
   브랜치명에서 슬래시(`/`)는 하이픈(`-`)으로 치환해. (예: `feat/ui-5` → `pr-feat-ui-5.md`)

## 출력 형식

아래 템플릿을 **정확히** 따라서 작성해. 이모지와 섹션 구조를 그대로 유지해.

```markdown
## 📌 PR 개요

{브랜치의 목적을 1~2문장으로 요약. 무엇을 구현/변경했고, 어떤 목표를 달성하는지 작성}

## 🔍 관련 이슈

Closes #

## 🔧 PR 유형

{해당하는 항목에 [x] 표시. 해당하지 않는 항목은 [ ] 유지}

- [ ] ✨ feat (새로운 기능)
- [ ] 🐛 fix (버그 수정)
- [ ] ♻️ refactor (리팩토링)
- [ ] ⚙️ chore (빌드/환경설정)
- [ ] 🎨 style (스타일)
- [ ] 📝 docs (문서)

## ✨ 변경 사항

{변경된 파일들을 논리적인 그룹으로 묶어서 작성. 각 그룹은 ### 소제목 사용.
파일 경로나 컴포넌트명은 백틱으로 감싸고, 핵심 내용을 간결하게 설명.}

## ✅ 체크리스트

- [x] 코드가 정상 동작함
- [x] 빌드 및 실행 확인 완료
- [x] 리뷰어가 이해하기 쉽게 변경 이유를 설명했음

## 🤝 기타 참고

{리뷰어가 알아야 할 설계 결정, 트레이드오프, 향후 작업 등. 없으면 이 섹션 생략.}
```

## 주의사항

- `docs/` 폴더에 이미 같은 이름의 파일이 있으면 덮어쓰기 전에 알려줘.
- 변경 사항은 파일 단위 나열이 아니라 기능/목적 단위로 그룹핑해.
- 실제 코드를 읽고 파악한 내용을 바탕으로 작성해. git log 메시지만 참고하지 마.
- 한국어로 작성해.
